# 检索辅助工具优化：减少读入与重复请求

定位：按需取证，减少无关读入与重复请求。辅助现有 agent，不接管会话记忆或压缩。
通用核心、MCP 接口、本机适配分开；当前只部署到这个 Codex 工作区。

## 最终配置的实测

沿用 323 万参考 Token 的 CPython 文档库和固定 22 道题，重新进行 20 次真实 Jev 评分。
两题没有候选，未发请求。随后重复查询，并测试调用方显式传入已在上下文中的证据引用。
这是已知题集的回归验证，不是独立留出集，也不是端到端用户任务的耗时测试。

| 指标 | 原版本 | 最终默认配置 |
| --- | ---: | ---: |
| 英文指定证据首位命中 | 13/16 | 13/16 |
| 英文指定证据前三命中 | 14/16 | 14/16 |
| 返回参考 Token 中位数（22 题） | 3,146 | 1,493 |
| 返回参考 Token 中位数（20 道有标签题） | 3,146 | 1,497.5 |
| 首次评分管线耗时中位数 | 856.92 ms | 851.05 ms |
| 同题缓存查询中位耗时 | 原版没有评分缓存 | 30.45 ms |
| 缓存查询的 Jev 请求 | 原版会再次请求 | 0 |
| 显式已在上下文时的返回 Token 中位数 | 原版重复返回正文 | 150 |

返回量中位数减少约 52.5%；显式重复查询相对旧版中位数减少约 95.2%。
Token 是 `cl100k_base` 对结果对象的计数，不包含宿主 MCP 包装或日志，也不代表账单或整个任务用量。
缓存加速只对同一问题、相同资料/候选和有效缓存成立，首次查询约 0.85 秒的成本仍然存在。
最终回归 API 输入 102,834 Token、输出 4,652 Token，与旧版本首轮相同。
因此首次省的是主模型读入量；重复命中缓存才省掉评分请求。

## 已实现

1. 默认最多 3 段完整原文、2,200 参考 Token 预算；同文档来源信息只列一次。
2. 评分缓存 1 小时；问题、候选内容、项目资料版本或评分版本变化即不复用。失败不缓存，Key 不入库。
3. 显式上下文去重。`ref` 绑定项目、来源、版本哈希及字符范围；调用方确认原文仍在上下文时才传 `known_refs`。不隐式追踪会话。
4. Jev 最高相关分低于 0.2 时返回 `insufficient_evidence`。这是扩检信号，不是已校准的可回答性判断。
5. 无候选或仅一个候选不请求重排；单候选跳过评分不等于确认相关。
6. 通用 Python 核心、CLI、MCP；当前机器的凭据处理仅在 `codex_host.py`。

资料新增/变更会使该项目评分缓存失效。旧原文仍保存。压缩或任务交接后，应重新判断哪些文字仍在当前上下文，不能盲目复用已读引用。
到期评分记录目前仅逻辑失效，没有自动清理或容量控制。

## 没有采用的默认优化

- 650 字符预览：实验组合中，指定证据首位命中降到 9/16，同组完整片段为 13/16，没有作为默认。
- 双路词形检索：有得有失，没有稳定净收益；保留为 `recall='expanded'` 诊断选项，默认沿用原候选策略。

探索记录是 `results.json`、`summary.json`；最终配置单独记录为 `release-results.json`、`release-summary.json`，不混算成绩。
词形检索采用 [SQLite Porter tokenizer](https://www.sqlite.org/fts5.html#porter_tokenizer)，是英文词形归一化，不是多语言语义检索。

## 当前 Codex 接入

项目 MCP 配置已指向 `codex_host.py`；MCP 重连后加载。当前对话也可用命令工具调用同一个适配器。
适配器临时读取已获准使用的本机 Claude 配置中的 TypeSafe Key，不复制密钥。
`approved-public-snapshots.json` 记录两个已批准公开资料项目的来源和内容哈希。
仅完整匹配的快照自动调用 Jev；新资料或新版本会退回本地，不自动扩大外发范围。
通用 `server.py` 不知道 Claude 配置路径，默认不联网；其他系统可提供自己的环境与凭据。

验证：16 项自动化检查通过；通用 MCP 搜索读取、本机适配的真实评分缓存、显式上下文去重和未批准项目禁用外部评分均通过。
本机 MCP 实测同题返回 1,497 参考 Token；传入已在上下文中的引用后返回 151，均复用真实评分缓存。

## 后续验收方向

在未见资料/问题上验证多语言语义召回、跨文件问题、版本冲突；再补批量读取和选定工具的大输出入库。
最终应测真实任务成功率、补读次数、所有模型合计用量和交互等待时间。
当前支持“返回更少、重复请求更快”的结论，尚不支持“所有任务都更快、更省钱”。
